I have just written our first major piece of code: log_telemetry.py. This script is designed to connect to your drone simulator, listen for the exact telemetry messages your thesis requires (GPS, Attitude, VFR_HUD, and Heartbeat), and log them into a CSV file with a clean 0 label for "Normal Flight".

To generate our first baseline dataset, we need to spin up the drone simulator and run our new script!

Since the simulator is interactive, you will need two separate terminals for this.

Terminal 1: Start the Drone Simulator
Open a new terminal window and run:

bash
cd /home/thigan/ardupilot/ArduCopter
sim_vehicle.py -v ArduCopter -f quad --console --map
Note: Since this is the very first time running it, it will compile the drone firmware code which may take 3-5 minutes. Once it's done, a map and a console window should pop up showing a virtual drone.

Terminal 2: Run the Logging Script
Once the drone map has opened in Terminal 1, go back to your original terminal (where our Python venv is located) and run the script:

bash
cd "/home/thigan/Desktop/FYP PROJECT"
source venv/bin/activate
python log_telemetry.py --out normal_flight_data.csv --label 0
You should see an output saying it is waiting for a heartbeat, and then it will begin logging! You can let it run for a few minutes (e.g., let the drone sit there, or send it a simple takeoff command from the simulator console using mode guided then arm throttle then takeoff 10).

When you have about 5 minutes of normal data, press Ctrl+C in Terminal 2 to save the CSV file.

Let me know when you have your normal_flight_data.csv file, and we will move on to the exciting part: Writing the Cyberattacks!

The next step is to create the "malicious" dataset so our Machine Learning model has something to detect. I've just written a new script called simulate_attack.py which contains two nasty MAVLink attacks:

Mode Change Attack: Forces the drone to instantly abandon its mission and return to launch.
RC Override Attack: Hijacks the physical remote control channels (forcing maximum throttle and roll) to crash the drone.
To run this safely, we need to send the drone's telemetry to two different ports so our scripts don't fight over the connection.

Step 1: Add a new connection port in the Simulator
Go to the terminal where your drone map and console are running (Terminal 1). At the STABILIZE> prompt, type:

bash
output add 127.0.0.1:14551
(This tells the drone to broadcast its telemetry to a second port).

Step 2: Start Logging Attack Data
Go to your second terminal (where your python environment is) and run the logging script, but this time we label it as 1 (Attack):

bash
python3 log_telemetry.py --out attack_flight_data.csv --label 1
Step 3: Launch the Cyberattack!
Open a third terminal window, activate your environment, and launch the RC override attack on the new port!

bash
cd "/home/thigan/Desktop/FYP PROJECT"
source venv/bin/activate
python3 simulate_attack.py --connect udp:127.0.0.1:14551 --attack rc_override
Watch the drone map—you should see it spin out of control or behave erratically! Let the logging script record this chaos for a few minutes, then press Ctrl+C to save attack_flight_data.csv.
